# Подключение и тестирование Robokassa

Пошаговая инструкция по настройке приёма оплаты через Robokassa в проекте irinaexamprep и проверке в тестовом режиме.

---

## Если вы делаете сайт заказчику (без своего ИП/юрлица)

По [официальному быстрому старту Robokassa](https://docs.robokassa.ru/ru/quick-start) для приёма платежей **на свой сайт** нужно: зарегистрировать личный кабинет, получить MerchantLogin и пароли, указать ResultURL, SuccessURL, FailURL. **Регистрировать Robokassa и создавать магазин должен тот, кто будет получать деньги** — владелец сайта (ваш заказчик), а не вы как разработчик.

**Как тестировать без открытия ИП на себя:**

1. **Регистрируется заказчик** — человек, для которого вы делаете сайт. Он заходит на [robokassa.ru](https://www.robokassa.ru/), регистрируется, создаёт магазин. Реквизиты для приёма платежей (ИП/самозанятость/ООО) указывает он — к моменту боевого запуска у него уже будет статус для приёма денег.
2. **Заказчик включает тестовый режим** в настройках магазина и заполняет минимум данных, необходимых для теста (в т.ч. реквизиты, если система их запрашивает).
3. **Заказчик передаёт вам тестовые данные:** MerchantLogin, Пароль #1, Пароль #2. Вы подставляете их в `.env.local` и проверяете сценарий «кнопка Оплатить → форма Robokassa → возврат на сайт». Деньги в тестовом режиме не списываются.
4. **Вы не открываете ИП/самозанятость/юрлицо** — вы только интегрируете код и тестируете по выданным заказчиком данным.

**Демомагазин Robokassa** (упоминается в [документации](https://docs.robokassa.ru/ru/quick-start)) — это страница _на стороне Robokassa_ для пробы оплаты (виджеты, примеры). Он не даёт «свою» ссылку на оплату с _вашего_ домена: чтобы кнопка на вашем сайте вела на платёжную форму и возвращалась обратно, нужен **магазин в личном кабинете** (его создаёт заказчик).

**Итог:** полноценно протестировать цепочку «ваш сайт → Robokassa → возврат» без чьей-либо регистрации в Robokassa нельзя. Минимальный вариант — регистрация заказчика, создание тестового магазина и передача вам логина и паролей для подстановки в проект.

## Быстрый тест без регистрации (демо-данные)

Стандартные демо-данные Robokassa (для проверки логики интеграции):

| Параметр                                        | Значение     |
| ----------------------------------------------- | ------------ |
| **MerchantLogin**                               | `demo`       |
| **Пароль #1** (инициация платежа)               | `Password_1` |
| **Пароль #2** (проверка уведомлений Result URL) | `Password_2` |

В `.env.local` укажите:

```env
NEXT_PUBLIC_SITE_URL=http://localhost:3000
ROBOKASSA_LOGIN=demo
ROBOKASSA_PASS1=Password_1
ROBOKASSA_PASS2=Password_2
ROBOKASSA_TEST=1
```

**Важно:** при использовании этих данных на **своём сайте** Robokassa может показать **ошибку 26 («Оплата счетов недоступна»)**. Она часто возникает, когда у магазина не заполнены реквизиты для приёма платежей или идентификатор «demo» недоступен для сторонних сайтов. Для стабильного теста нужна **регистрация в Robokassa**, создание магазина, заполнение реквизитов и включение тестового режима — см. разделы 1–2 ниже.

---

## 1. Регистрация и доступ в личный кабинет

1. Зайдите на [robokassa.ru](https://www.robokassa.ru/).
2. Зарегистрируйтесь или войдите в личный кабинет.
3. Перейдите в раздел **«Технические настройки»** (или **«Настройки магазина»** → **«Технические настройки»**).

---

## 2. Настройка тестирования (магазин cambridge_exams_and_methodology)

По скриншоту «Технические настройки» / «Параметры проведения тестовых платежей» нужно сделать следующее.

### В личном кабинете Robokassa

**Технические настройки (основной блок):**

| Поле                            | Сейчас у вас                | Нужно указать                                    |
| ------------------------------- | --------------------------- | ------------------------------------------------ |
| **Result URL**                  | `http://irinaexamprep.com/` | `https://irinaexamprep.com/api/pay/result`       |
| **Метод отсылки по Result URL** | GET                         | Оставить GET (в коде обрабатываются GET и POST). |
| **Success URL**                 | `http://irinaexamprep.com/` | `https://irinaexamprep.com/methodology`          |
| **Fail URL**                    | `http://irinaexamprep.com/` | `https://irinaexamprep.com/methodology`          |

**Важно:** при методе отсылки **GET** Robokassa не разрешает параметры в URL (`?payment=success` и т.п.). Указывайте адреса **без** параметров: только `https://irinaexamprep.com/methodology` для Success и Fail. Редирект после оплаты при этом всё равно ведёт на нужную страницу с параметрами: при каждом создании платежа наш сервер передаёт в запросе к Robokassa свои SuccessURL и FailURL с `?payment=success` и `?payment=fail`, и именно они используются при переходе пользователя. Значения из кабинета — запасной вариант.

**Result URL** обязательно должен быть именно `/api/pay/result` — на этот адрес Robokassa шлёт уведомление об оплате. По возможности используйте **https**, а не http.

**Параметры проведения тестовых платежей (нижний блок):**

- Алгоритм хеша: **MD5** — в коде уже используется MD5, менять не нужно.
- **Пароль #1** и **Пароль #2** — должны быть заданы (у вас «Пароль задан»). Эти же пароли нужно подставить в `.env.local` (см. ниже). Если пароли ещё не знаете — нажмите «Сгенерировать», сохраните настройки и вставьте выданные значения в переменные окружения.

### В проекте (.env.local)

Уже подставлены логин магазина и включён тест. Осталось вписать **тестовые** пароли из блока «Параметры проведения тестовых платежей»:

```env
ROBOKASSA_LOGIN=cambridge_exams_and_methodology
ROBOKASSA_PASS1=сюда_пароль_1_из_тестового_блока
ROBOKASSA_PASS2=сюда_пароль_2_из_тестового_блока
ROBOKASSA_TEST=1
NEXT_PUBLIC_SITE_URL=https://irinaexamprep.com
```

После сохранения настроек в кабинете нажмите **«Сохранить»** внизу страницы.

## 2a. Получение тестовых данных (песочница) — общее

Для проверки без реальных денег можно использовать **демо-данные** (см. блок выше) или **свой тестовый магазин** в Robokassa.

Если настраиваете свой магазин:

1. В личном кабинете найдите раздел **«Тестовый режим»** / **«Песочница»**.
2. Включите тестовый режим для магазина.
3. Скопируйте и сохраните:
   - **Идентификатор магазина (Merchant Login)** — например, `demo` или ваш тестовый логин.
   - **Пароль #1** — используется при формировании ссылки на оплату (SignatureValue при переходе пользователя).
   - **Пароль #2** — используется при проверке уведомления Result URL (подтверждение оплаты на вашем сервере).

Пароли задаются в настройках магазина. Пароль #2 должен быть не менее 8 символов, содержать буквы и цифры и отличаться от пароля #1.

---

## 3. Настройка URL в личном кабинете Robokassa

В **«Технических настройках»** укажите:

| Поле            | Значение                               | Пояснение                                                                                                                                 |
| --------------- | -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **Result URL**  | `https://ваш-домен.com/api/pay/result` | Адрес, на который Robokassa отправит запрос после успешной оплаты. Должен быть доступен из интернета по HTTPS (порты 80/443).             |
| **Success URL** | Уже передаётся из кода                 | В коде задаётся как `NEXT_PUBLIC_SITE_URL/methodology?payment=success`. Можно не дублировать в кабинете, если передаёте в каждом запросе. |
| **Fail URL**    | Аналогично                             | `NEXT_PUBLIC_SITE_URL/methodology?payment=fail`.                                                                                          |

- Для **локального теста** Result URL из интернета недоступен. Ниже описано, как тестировать через ngrok или аналог.
- Метод уведомления Result URL: в настройках можно выбрать **GET** или **POST**; в проекте обрабатываются оба.

## 4. Переменные окружения (.env.local)

Создайте файл `.env.local` в корне проекта и заполните:

```env
# Обязательно для редиректов после оплаты (подставьте свой домен или ngrok для теста)
NEXT_PUBLIC_SITE_URL=https://ваш-домен.com

# Robokassa
ROBOKASSA_LOGIN=ваш_логин_магазина
ROBOKASSA_PASS1=пароль_номер_1
ROBOKASSA_PASS2=пароль_номер_2

# Тестовый режим: 1 или true — оплата идёт в песочницу Robokassa (деньги не списываются)
ROBOKASSA_TEST=1
```

После перехода на боевой режим выставьте `ROBOKASSA_TEST=0` или удалите переменную и укажите боевые логин и пароли.

---

## 5. Как в проекте устроена оплата

- **Создание платежа:** пользователь на странице «Методика» нажимает оплату → фронт отправляет `POST /api/pay` с `outSum`, `email` (и при необходимости `productId`). Сервер формирует подпись (Пароль #1), возвращает `redirectUrl` на Robokassa.
- **Переход на Robokassa:** пользователь перенаправляется по `redirectUrl`, вводит данные карты в тестовой/боевой форме Robokassa.
- **Result URL:** после успешной оплаты Robokassa вызывает `GET` или `POST /api/pay/result` с параметрами `OutSum`, `InvId`, `SignatureValue`. Сервер проверяет подпись с **Паролем #2** и отвечает `OK{InvId}` или `ERROR`.
- **Success / Fail:** пользователь возвращается на `SuccessURL` или `FailURL` (в коде — `/methodology?payment=success` или `?payment=fail`).

Файлы в проекте:

- `src/app/api/pay/route.ts` — создание платежа и выдача `redirectUrl`.
- `src/app/api/pay/result/route.ts` — приём Result URL и ответ `OK{InvId}`/`ERROR`.

## 6. Тестирование локально (Result URL с интернета)

Result URL должен быть доступен по HTTPS с интернета. Локально это можно сделать так:

1. Запустите приложение: `npm run dev`.
2. Поднимите туннель (например, [ngrok](https://ngrok.com/)):
   ```bash
   ngrok http 3000
   ```
3. Скопируйте выданный HTTPS-URL (например, `https://abc123.ngrok.io`).
4. В **.env.local** задайте:
   ```env
   NEXT_PUBLIC_SITE_URL=https://abc123.ngrok.io
   ```
5. В личном кабинете Robokassa в **Result URL** укажите:
   ```text
   https://abc123.ngrok.io/api/pay/result
   ```
6. Перезапустите `npm run dev`, откройте сайт через ngrok-URL, сделайте тестовый платёж.

После оплаты в тестовом режиме Robokassa отправит запрос на `/api/pay/result`; в консоли сервера не должно быть ошибок, а в личном кабинете Robokassa можно проверить, что уведомление обработано (статус операции).

---

## 7. Тестовые карты (песочница Robokassa)

В тестовом режиме используйте тестовые карты из документации Robokassa (обычно на странице «Тестовый режим» или «Песочница»). Примеры часто такие:

- Номер карты: например, `4111 1111 1111 1111`.
- Срок и CVC — любые валидные (будущая дата, 3–4 цифры).

Актуальный список смотрите в разделе **«Тестовый режим»** в [документации Robokassa](https://docs.robokassa.ru/).

---

## 8. Переход на боевой режим

1. В личном кабинете Robokassa заполните данные магазина и пройдите модерацию (если требуется).
2. В настройках магазина задайте **боевые** Пароль #1 и Пароль #2.
3. В **.env.local** на продакшене:
   - `ROBOKASSA_LOGIN` — боевой логин магазина.
   - `ROBOKASSA_PASS1` и `ROBOKASSA_PASS2` — боевые пароли.
   - `ROBOKASSA_TEST=0` или удалите переменную.
   - `NEXT_PUBLIC_SITE_URL` — боевой домен (например, `https://irinaexamprep.com`).
4. В технических настройках укажите боевой **Result URL**: `https://ваш-боевой-домен.com/api/pay/result`.
5. Сделайте один тестовый платёж на минимальную сумму и проверьте, что на Result URL приходит запрос и возвращается `OK{InvId}`.

## 9. Безопасность (по желанию)

- В документации Robokassa указаны IP для белого списка: `185.59.216.65`, `185.59.217.65`. Если у вас включена фильтрация входящих запросов, добавьте эти IP для маршрута `/api/pay/result`.
- Не храните пароли в коде — только в переменных окружения (.env.local не коммитить).

## 10. Ошибка 26 («Оплата счетов недоступна»)

Код **26** значит, что Robokassa не разрешает приём платежей для этого магазина. По шагам проверьте:

1. **Реквизиты магазина**  
   В личном кабинете: **Настройки магазина** (или **Реквизиты** / **Данные для приёма платежей**). Должны быть заполнены: расчётный счёт, банк, ИНН, название получателя и т.п. Без этого тестовые и боевые платежи часто дают ошибку 26.

2. **Тестовый режим включён**  
   В настройках магазина должен быть **включён тестовый режим** (песочница). Идентификатор магазина — `cambridge_exams_and_methodology`, пароли берутся из блока **«Параметры проведения тестовых платежей»** (не из основного блока «Технические настройки»).

3. **Логин и пароли в .env**  
   В переменных окружения (Vercel / .env.local):
   - `ROBOKASSA_LOGIN=cambridge_exams_and_methodology` — без опечаток.
   - `ROBOKASSA_PASS1` и `ROBOKASSA_PASS2` — **именно** тестовые пароли из раздела «Параметры проведения тестовых платежей».
   - `ROBOKASSA_TEST=1`.

4. **Магазин в процессе активации**  
   Если в кабинете указано «Магазин в процессе активации» — это типичная причина ошибки 26. Пока Robokassa не завершит проверку и не активирует магазин, приём платежей (в т.ч. тестовых) недоступен. Нужно дождаться смены статуса на «Активирован» (обычно 1–3 рабочих дня). При задержке можно уточнить сроки в поддержке Robokassa ([robokassa.ru](https://www.robokassa.ru/), Telegram @robosupport_bot).

После изменений в кабинете сохраните настройки и сделайте повторный платёж.

## 11. Частые проблемы

| Проблема                            | Что проверить                                                                                                                           |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| **Ошибка 26**                       | См. раздел 10 выше.                                                                                                                     |
| «Оплата временно недоступна»        | В .env.local заданы `ROBOKASSA_LOGIN` и `ROBOKASSA_PASS1`.                                                                              |
| Не возвращается ссылка на оплату    | В ответе от `POST /api/pay` смотреть поле `error` и логи сервера.                                                                       |
| Result URL не вызывается            | Result URL доступен из интернета по HTTPS; в кабинете указан верный URL; при локальном тесте — использовать ngrok.                      |
| Result URL возвращает ERROR         | Совпадает ли подпись: используется **Пароль #2**, формула `OutSum:InvId:Пароль#2` (без Shp\_\*, как в коде). Проверить кодировку UTF-8. |
| После оплаты не редирект на success | Задан ли `NEXT_PUBLIC_SITE_URL` и совпадает ли домен с тем, с которого идёт запрос.                                                     |

Если что-то пойдёт не так, откройте консоль сервера (`npm run dev`) и сеть во вкладке «Методика» при нажатии «Оплатить» — по ответу `/api/pay` и логам `/api/pay/result` обычно видно причину.
