# План интеграции Storyblok

Клиент хочет управлять всем контентом сайта из одной CMS: заголовки, тексты, фото, блоки с видео, цены и т.д. **Реализовать это со Storyblok можно.**

---

## Что будет управляться из CMS


| Место на сайте                                   | Сейчас в коде                                        | Что отдаём в Storyblok                                                                                                         |
| ------------------------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| **Главная**                                      | `page.tsx` → title, description, imageUrl            | Hero: заголовок, описание, фото. Остальные секции — свои блоки/поля.                                                           |
| **Hero**                                         | Props + TEACHER_INTRO в HeroSection                  | Заголовок, подзаголовок, фото, текст под кнопками.                                                                             |
| **Обо мне (About)**                              | AboutSection: заголовок + 8 абзацев + 7 сертификатов | Заголовок, список абзацев, список картинок сертификатов.                                                                       |
| **Блок преимуществ (Features)**                  | features[] в FeaturesSection                         | Заголовок секции, подзаголовок, список: заголовок, описание, иконка (Lottie можно оставить по ключу или заменить на картинку). |
| **Курсы (страница /courses)**                    | COURSE_CARDS + COURSE_DESCRIPTIONS                   | Список курсов: название, slug, картинка, длинное описание.                                                                     |
| **Методика (/methodology)**                      | METHODOLOGY_VIDEOS                                   | Список модулей: id, videoId (YouTube), название, описание, цена.                                                               |
| **Отзывы (Testimonials)**                        | testimonials[]                                       | Список: имя, роль, текст, аватар, картинка сертификата.                                                                        |
| **Блок CTA**                                     | Заголовки, текст, ссылки в CTASection                | Заголовок, подзаголовок, текст кнопок, ссылки соцсетей.                                                                        |
| **Курсы/Методика/Ресурсы (карточки на главной)** | CoursesMethodologySection: заголовки, ссылки, lorem  | Заголовки карточек, ссылки «Подробнее», краткие тексты.                                                                        |
| **Шапка**                                        | Header: логотип, пункты меню                         | Текст логотипа, подпись, пункты меню (название + ссылка).                                                                      |
| **Подвал**                                       | Footer                                               | Текст копирайта, при желании ссылки.                                                                                           |
| **Оферта**                                       | Текст в offer/page.tsx                               | Один большой rich text или несколько блоков.                                                                                   |
| **Free Resources**                               | Заголовки, текст, ссылка на файл                     | Заголовок страницы, описание, ссылка на sample-download.                                                                       |


Фото и картинки хранятся в медиабиблиотеке Storyblok, ссылки на файлы отдаются через поля (Asset или ссылка).

## Два варианта интеграции

### Вариант A: «Одна история на тип страницы» (рекомендуется на старт)

- В Storyblok заводим **типы контента (Content types)** под страницы: Home, Courses, Methodology, Free Resources, Offer, + глобальный Config/Header/Footer.
- У каждой истории — **поля и повторяемые блоки** (например, список курсов, список отзывов). Структура страницы фиксирована (какие секции есть), редактируются только тексты, цены, медиа, ссылки.
- В Next.js по маршруту определяем, какую историю запрашивать (`home`, `courses`, `methodology` и т.д.), загружаем её через API Storyblok и **передаём данные в существующие компоненты** (HeroSection, AboutSection, courses-client и т.д.). Разметку и стили почти не трогаем.
- Плюсы: быстрее внедрить, меньше рефакторинга, клиенту проще править «формы» (поля и списки). Минус: добавлять новые типы блоков на страницу будет сложнее (нужны правки в коде и в типах Storyblok).

### Вариант B: «Всё блоками (Blok-based)»

- Каждая секция (Hero, About, Features, CourseCard, VideoBlock, Testimonials, CTA и т.д.) — **отдельный Blok** в Storyblok. Страница (например Home) — это «контейнер» с массивом блоков; редактор добавляет/удаляет/переставляет блоки.
- В Next.js один общий шаблон страницы: рендер по `story.content.body[]` и маппинг типа блока на React-компонент. Максимальная гибкость, но больше работы по схеме в Storyblok и по коду (каждый блок = компонент + тип в CMS).
- Имеет смысл переходить на это, когда клиенту понадобится самому собирать страницы из блоков и часто менять структуру.

**Практичный путь:** начать с **варианта A**, вынести весь текущий контент в Storyblok (заголовки, тексты, фото, цены, видео, списки). Когда потребуется «собирать страницу из блоков» — расширить модель до варианта B.

## Что нужно сделать технически

1. **Storyblok**
  - Зарегистрировать пространство (space) на [storyblok.com](https://www.storyblok.com).
  - Создать Content types и поля (см. таблицу выше).
  - Заполнить контент (скопировать с сайта или вручную).
  - В настройках пространства взять **Access Token** (Preview/Draft и при желании Public для продакшена).
2. **Проект (Next.js)**
  - Установить `@storyblok/react`.
  - Добавить в `.env.local`: `NEXT_PUBLIC_STORYBLOK_ACCESS_TOKEN=...`.
  - Инициализировать Storyblok (RSC или client) и заменить источники контента:
    - главная: запрос `cdn/stories/home` (или по slug) → передать в `HomeClient` и секции;
    - курсы: запрос данных для страницы курсов → в `courses-client`;
    - методика: запрос данных для методики → в `methodology-client`;
    - free-resources, offer — аналогично;
    - глобальные данные (шапка, подвал) — одна общая история или глобальный singleton, подставлять в Layout/Header/Footer.
  - Медиа: картинки из Storyblok отдаются URL вида `https://a.storyblok.com/...` — можно использовать `next/image` с доменом `a.storyblok.com` в `next.config`.
  - По желанию: включить **Visual Editor** (bridge) для редактирования контента с превью на сайте.
  - **Автообновление на Vercel:** при публикации в Storyblok сайт подхватывает изменения без ручного редеплоя — через webhook и On-Demand Revalidation (см. раздел ниже).
3. **Резерв (fallback)**
  - Пока контент не заполнен в Storyblok или при ошибке API — использовать текущие захардкоженные данные, чтобы сайт не падал.

После этого клиент сможет в Storyblok править заголовки, тексты, фото, цены, видео, списки курсов/отзывов/модулей и т.д. без правок в коде.

## Что уже сделано (пилот)

- Установлен `@storyblok/react`, в `.env.local` добавлена переменная `NEXT_PUBLIC_STORYBLOK_ACCESS_TOKEN`.
- В `next.config.ts` разрешён домен картинок `a.storyblok.com`.
- В `src/lib/storyblok.ts`: инициализация SDK (RSC), функция `fetchStory(slug)` для загрузки истории по slug.
- Главная страница: в `app/page.tsx` запрашивается история с slug **home**. Если токен не задан или запрос неудачен — используются захардкоженные значения (fallback).
- Hero-секция получает из Storyblok: `title`, `description`, `intro`, `image` (URL фото). Тип контента описан в `src/lib/storyblok-types.ts` (`HomeStoryContent`).

### Как создать историю «Главная» в Storyblok

1. В личном кабинете Storyblok: Content → создать новую историю.
2. Slug задать **home** (без слэша).
3. В блоке контента (или в Body) добавить блок **section_hero** (или **hero**) с полями:
  - **title** (Text) — заголовок, например «Ирина Петрова».
  - **description** (Text, опционально) — подзаголовок под кнопками.
  - **intro** (Textarea, опционально) — абзац про преподавателя (если пусто — используется текст по умолчанию из кода).
  - **image** (Asset) — фото преподавателя (если пусто — используется локальное фото с сайта).
4. Опубликовать историю (Publish).
5. В настройках пространства (Settings → Access tokens) скопировать **Preview/Draft** или **Public** токен и вставить в `.env.local` в `NEXT_PUBLIC_STORYBLOK_ACCESS_TOKEN`.

В **Body** истории home добавляются блоки: **section_hero** (или hero), **section_about**, **section_features** и т.д. (см. таблицу именования и таблицу блоков ниже).

## Структура историй: какая история для какой страницы

**Рекомендация:** одна страница сайта = одна история в Storyblok. Slug истории лучше совпадать с путём на сайте (или быть понятным). Так проще не запутаться и в коде подставлять slug по маршруту.


| Маршрут на сайте                         | Slug истории в Storyblok | Что хранить в истории                                                                                   |
| ---------------------------------------- | ------------------------ | ------------------------------------------------------------------------------------------------------- |
| `/` (главная)                            | **home**                 | Body с блоками: Hero, Обо мне, Преимущества, Отзывы, Карточки курсов, CTA, при желании Footer.          |
| — (глобальное)                           | **config**               | Шапка (логотип, меню) и подвал (текст реквизитов). Можно не создавать, если футер лежит в Body главной. |
| `/courses` (Language Courses)            | **courses**              | Заголовок страницы, список курсов (название, slug, описание, картинка).                                 |
| `/methodology` (Методика)                | **methodology**          | Заголовок, список модулей (видео YouTube, название, описание, цена).                                    |
| `/free-resources` (Free resources)       | **free-resources**       | Заголовок, описание, ссылка на файл (например sample PDF).                                              |
| `/offer` (Публичная оферта)              | **offer**                | Заголовок (опционально), основной текст оферты (Rich text или блоки абзацев).                           |
| `/payment-refund` (Оплата и возврат)     | **payment-refund**       | Заголовок (опционально), текст страницы (Rich text или блоки).                                          |
| `/privacy` (Политика конфиденциальности) | **privacy**              | Заголовок (опционально), текст политики (Rich text или блоки).                                          |


**Как создавать:**

1. **Content** → **+ New** → **Story** (или папка, внутри — Story).
2. В поле **Slug** ввести значение из таблицы (**courses**, **methodology**, **offer** и т.д.) — латиницей, без пробелов; для «Оплата и возврат» — **payment-refund**, для «Free resources» — **free-resources**.
3. Выбрать нужный **Content type** (или один универсальный тип «Page» с разными блоками).
4. Заполнить поля/блоки контента и нажать **Publish**.

**Текстовые страницы (оферта, оплата, политика):** достаточно одного поля **content** или **body** типа **Rich text** (или список блоков «абзац» с полем **text**). В коде страницы (/offer, /payment-refund, /privacy) потом запрашивается история по slug и выводится этот контент. Подключение этих страниц к Storyblok — следующий шаг после настройки главной и config.

**Итог:** создай отдельные истории **courses**, **methodology**, **free-resources**, **offer**, **payment-refund**, **privacy** с указанными slug. Контент внутри каждой — по таблице выше. Когда будешь подключать страницы в коде, по маршруту будет запрашиваться соответствующая история (например для `/offer` — `fetchStory('offer')`).

### Именование блоков: привязка к секциям

Чтобы блоками было проще управлять (в том числе тем, кто не писал код), используем **понятные имена с привязкой к секциям**. В коде заданы рекомендуемые имена; старые тоже поддерживаются для обратной совместимости.


| Секция на сайте                       | Рекомендуемое имя блока в Storyblok | Старые имена (работают) | Как подписать в UI (Display name) |
| ------------------------------------- | ----------------------------------- | ----------------------- | --------------------------------- |
| Hero (верх главной)                   | **section_hero**                    | hero                    | «Hero» / «Верх главной»           |
| Обо мне                               | **section_about**                   | about                   | «Секция „Обо мне“»                |
| Преимущества (3 карточки)             | **section_features**                | features                | «Секция „Преимущества“»           |
| Отзывы студентов                      | **section_testimonials**            | testimonials            | «Секция „Отзывы“»                 |
| Карточки: Курсы, Методика, Ресурсы    | **section_courses_cards**           | courses_section         | «Секция „Карточки курсов“»        |
| Призыв к действию (подписка, соцсети) | **section_cta**                     | cta                     | «Секция „Призыв к действию“»      |


В **Block Library** при создании блока указывайте **имя** (Name) = рекомендуемое имя из таблицы (например `section_about`). Если в Storyblok есть поле **Display name** / **Label** для типа блока — задайте туда подпись из последней колонки, чтобы в списке блоков при добавлении в Body было видно «Секция „Обо мне“» вместо `section_about`. Константа имён в коде: `app/page.tsx` → `HOME_BLOCK_NAMES`.

**Вложенные блоки (БЭМ-стиль):** имена привязываем к родителю через префикс родительского блока, без двойного подчёркивания — один блок = один «элемент» родителя.


| Родительский блок     | Поле         | Имя вложенного блока (рекомендуемое) | Старые имена (работают) |
| --------------------- | ------------ | ------------------------------------ | ----------------------- |
| section_about         | paragraphs   | **section_about_paragraph**          | paragraph               |
| section_about         | certificates | **section_about_certificate**        | certificate             |
| section_features      | items        | **section_features_item**            | feature_item            |
| section_testimonials  | items        | **section_testimonials_item**        | testimonial_item        |
| section_courses_cards | cards        | **section_courses_cards_card**       | card                    |
| section_cta           | links        | **section_cta_link**                 | cta_link                |
| methodology_page     | modules      | **methodology_module**                | —                       |
| free_resources_page  | resources    | **free_resources_page_resource**     | free_resource_item      |


В Block Library создавайте вложенные блоки с рекомендуемыми именами (или переименуйте существующие). В родительском блоке в поле типа Blocks в «Allowed block types» указывайте этот вложенный блок. Код не проверяет `component` у элементов массива — подойдут любые имена.

### Блоки главной страницы (добавлять в Body истории home)

Все блоки добавляются в историю **home** через «+ Add Block». Используйте **рекомендуемые имена** из таблицы выше (латиница, без пробелов).


| Имя блока (component)     | Секция            | Поля блока                                                                                                                   |
| ------------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **section_hero**          | Hero              | title, description, intro, image (Asset)                                                                                     |
| **section_about**         | Обо мне           | title, paragraphs (Blocks: **section_about_paragraph**), certificates (Blocks: **section_about_certificate**), image (Asset) |
| **section_cta**           | Призыв к действию | title, subtitle, privacy_consent_text, links (Blocks: **section_cta_link** — url/link, label, type: telegram                 |
| **section_features**      | Преимущества      | title, subtitle, items (title, description, animation_key: calendar                                                          |
| **section_testimonials**  | Отзывы            | title, items (Blocks: **section_testimonials_item** — name, role, text, avatar, certificate_image)                           |
| **section_courses_cards** | Карточки курсов   | cards (Blocks: **section_courses_cards_card** — title, link, description; 3 элемента)                                        |


Порядок блоков в Body не важен: код ищет блок по имени. Если блока нет — секция использует захардкоженные данные.

#### Блок Hero (section_hero) — верх главной страницы

Соответствует компоненту **HeroSection**: заголовок, подзаголовок, текст под кнопками, фото преподавателя.


| Поле в Config      | Значение                                                                                    |
| ------------------ | ------------------------------------------------------------------------------------------- |
| **Technical name** | `section_hero`                                                                              |
| **Display name**   | `Section Hero` или «Hero» / «Верх главной»                                                  |
| **Description**    | Верхний блок главной страницы: заголовок, подзаголовок, краткий текст и фото преподавателя. |
| **Block type**     | Nestable block                                                                              |


**Поля блока (вкладка Fields):**


| Key             | Тип поля              | Обязательность                 | Описание                                                                                    |
| --------------- | --------------------- | ------------------------------ | ------------------------------------------------------------------------------------------- |
| **title**       | Single line           | да (иначе подставится из кода) | Заголовок, например «Ирина Петрова».                                                        |
| **description** | Single line           | нет                            | Подзаголовок под кнопками.                                                                  |
| **intro**       | Multi-line / Textarea | нет                            | Текст про преподавателя под кнопками; если пусто — используется текст по умолчанию из кода. |
| **image**       | Asset (Image)         | нет                            | Фото преподавателя; если пусто — используется локальное фото с сайта.                       |

#### Блок «Обо мне» (section_about) — секция AboutSection

| Поле в Config      | Значение                                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------------- |

| **Block type**     | Nestable block                                                                                     |


**Поля блока (вкладка Fields):**


| Key              | Тип поля      | Обязательность | Описание                                                                                             |
| ---------------- | ------------- | -------------- | ---------------------------------------------------------------------------------------------------- |
| **title**        | Single line   | нет            | Заголовок секции; если пусто — на сайте «Обо мне».                                                   |
| **paragraphs**   | Blocks        | нет            | Список абзацев. Разрешить один тип: **section_about_paragraph** (см. «Настройка вложенных блоков»).  |

**Вложенный блок section_courses_cards_card** (один элемент из **cards**, БЭМ-стиль: родитель section_courses_cards + элемент card):

## Подробная пошаговая настройка в Storyblok

Ниже — пошаговые действия в интерфейсе Storyblok: куда заходить, что нажимать и какие типы полей выбирать.

**Оглавление раздела:**

- **Где что находится** — Block Library, Content, типы полей (Single line, Multi-line, Asset, Blocks).
- **Блок «Обо мне» (section_about)** — подробно: section_about_paragraph, section_about_certificate → section_about → добавление в home. Отдельное описание: [docs/STORYBLOK_ABOUT.md](docs/STORYBLOK_ABOUT.md).
- **Блок «Преимущества» (section_features)** — подробно: section_features_item → section_features → добавление в home.
- **Блок отзывов (section_testimonials)** — подробно: section_testimonials_item → section_testimonials → добавление в home.
- **Блок карточек (section_courses_cards)** — подробно: section_courses_cards_card → section_courses_cards → добавление в home.
- **Блок «Призыв к действию» (section_cta)** — подробно: section_cta_link → section_cta → добавление в home.
- **Блок Hero (section_hero)** — кратко: создание блока section_hero и добавление в home.

---

### Где что находится в Storyblok

- **Левое меню:** внизу слева — **Block Library** (или **Blocks**). Здесь создаются и редактируются **типы блоков** (схема полей). Отдельно в меню есть **Content** — здесь живут **истории** (страницы контента: home, config и т.д.).
- **Content:** нажми **Content** → откроется список папок/историй. Выбери историю (например **home**) — откроется редактор. В нём есть поле **Body** (или подобное), куда добавляются блоки (section_hero, section_about, section_testimonials и т.д.). Чтобы блок появился в списке, его тип нужно сначала создать в Block Library.
- **Типы полей в Storyblok** (при добавлении поля в блок):
  - **Single line** — одна строка текста (заголовки, подписи, ссылки).
  - **Multi-line** или **Textarea** — многострочный текст (абзацы, описания).
  - **Asset** (или **Image**) — загрузка картинки из медиабиблиотеки.
  - **Blocks** — список повторяемых блоков (например список абзацев или сертификатов). После выбора типа **Blocks** нужно указать, какие типы блоков разрешены (например только **section_about_paragraph** или **section_about_certificate**).
  - **Link** — ссылка (в некоторых блоках, например section_courses_cards).

Имена полей (Key) вводи **латиницей**, без пробелов: `title`, `paragraphs`, `certificates`, `image`, `text`, `alt` и т.д. — как в таблице блоков выше.

### Пошагово: блок «Обо мне» (section_about)

Секция с заголовком, абзацами текста, фото и сеткой сертификатов. Порядок: создаём вложенные блоки **section_about_paragraph** и **section_about_certificate**, затем блок **section_about**, потом добавляем его в историю **home**.

#### Шаг 1. Создать блок одного абзаца (section_about_paragraph)

1. В левом меню нажми **Block Library** (или **Blocks**).
2. Нажми **+ New Block** (или кнопку «Create new block» / «Type to create a new block»).
3. В поле имени блока введи: **section_about_paragraph** (БЭМ-стиль: элемент paragraph родителя section_about). Создай блок.
4. Откроется редактор блока **section_about_paragraph**. Нужно добавить одно поле:
  - Нажми **Add field** (или **+ Field**).
  - **Key (имя поля):** введи **text**.
  - **Type:** выбери **Multi-line** или **Textarea**.
  - Сохрани блок (кнопка **Save** вверху).

#### Шаг 2. Создать блок одного сертификата (section_about_certificate)

1. Снова в **Block Library** нажми **+ New Block**.
2. Имя блока: **section_about_certificate** (БЭМ-стиль: элемент certificate родителя section_about). Создай.
3. В блоке **section_about_certificate** добавь два поля:
  - Поле 1: **Key** — **image**, **Type** — **Asset** (или **Image**). Это картинка сертификата.
  - Поле 2: **Key** — **alt**, **Type** — **Single line**. Это подпись к картинке (например «Сертификат CELTA»).
4. **Save**.

#### Шаг 3. Создать блок section_about и привязать paragraph и certificate

1. В **Block Library** нажми **+ New Block**.
2. Имя блока: **section_about** (рекомендуемое; в Display name можно указать «Секция „Обо мне“»). Создай.
3. В блоке **section_about** добавь четыре поля по очереди:
  **Поле 1 — заголовок**
  - **Key:** **title**
  - **Type:** **Single line**
  - Сохрани поле.
   **Поле 2 — абзацы**
  - **Key:** **paragraphs**
  - **Type:** **Blocks**
  - В «Allowed block types» добавь блок **section_about_paragraph** (или **paragraph**). Сохрани поле.
   **Поле 3 — сертификаты**
  - **Key:** **certificates**
  - **Type:** **Blocks**
  - В разрешённых блоках укажи **section_about_certificate** (или **certificate**). Сохрани поле.
   **Поле 4 — фото**
  - **Key:** **image**
  - **Type:** **Asset** (или **Image**)
  - Сохрани поле.
4. Нажми **Save** у самого блока **section_about**.

#### Шаг 4. Добавить блок section_about на главную (home)

1. В левом меню открой **Content**.
2. Выбери историю **home** (если нет — создай: **+ New** → Story, **Slug** = **home**).
3. В редакторе найдите **Body**. Нажми **+ Add block**.
4. В списке выбери блок **section_about** (или «Секция „Обо мне“», если задан Display name).
5. Откроется форма блока **section_about**:
  - **title** — введи заголовок секции, например «Обо мне».
  - **image** — нажми на поле и загрузи фото преподавателя (или выбери из медиабиблиотеки).
  - **paragraphs** — добавь элементы **section_about_paragraph**; в каждом в поле **text** введи текст абзаца. Порядок = порядок на сайте.
  - **certificates** — добавь элементы **section_about_certificate**; в каждом укажи **image** и **alt** (например «Сертификат CELTA»).
6. Нажми **Save** вверху страницы истории.
7. Опубликуй контент: кнопка **Publish** (или **Publish story**).

После публикации сайт подхватит блок **section_about**: заголовок, абзацы, фото и сертификаты — из Storyblok. Если блок не добавлять или оставить поля пустыми, секция покажет данные по умолчанию из кода.

### Пошагово: блок «Преимущества» (section_features)

Секция с заголовком, подзаголовком и карточками преимуществ (заголовок, описание, Lottie по ключу calendar / clock / consultation).

#### Шаг 1. Создать блок одной карточки (section_features_item)

1. В левом меню нажми **Block Library**.
2. Нажми **+ New Block**.
3. В поле имени введи: **section_features_item** (БЭМ: элемент item родителя section_features). Display name можно указать «Одна карточка преимущества». Создай блок.
4. В блоке **section_features_item** добавь три поля:

### Инструкция: дополнительные подзаголовки (тайтлы) на клиенте

На страницах **Оплата и возврат** и **Политика конфиденциальности** можно вынести вводные и заключительные фразы в отдельные поля в Storyblok. На сайте они отображаются как подзаголовки: тот же стиль, что у заголовков секций (крупный жирный текст, цвет темы).

**Что сделать в Storyblok:**

1. **Оплата и возврат** (контент-тип `payment_refund_page`): добавить поле **subtitle** (Single line или Textarea). Текст из этого поля показывается под основным заголовком страницы одним блоком с выделением.
2. **Политика конфиденциальности** (контент-тип `privacy_page`): добавить поля **subtitle_1**, **subtitle_2**, **footer_title** (каждое — Single line или Textarea). `subtitle_1` и `subtitle_2` показываются под основным заголовком по очереди; `footer_title` — внизу страницы после основного текста.

**Важно:** имена полей должны быть именно **subtitle** (для payment-refund), **subtitle_1**, **subtitle_2**, **footer_title** (для privacy). Код на клиенте читает эти ключи и применяет к ним стили подзаголовков. Остальные строковые поля из контента тоже передаются в `customFields`, но на страницах пока используются только перечисленные.

## Автообновление контента (Vercel + webhook)

Чтобы при публикации в Storyblok сайт на Vercel сразу показывал новый контент (без ручного редеплоя), используется **On-Demand Revalidation**.

**Как это устроено:** при нажатии «Publish» в Storyblok вызывается ваш API; он говорит Next.js инвалидировать кэш указанных страниц — при следующем заходе пользователя данные подтягиваются из Storyblok заново.

**1. Переменная в Vercel**

1. Vercel → ваш проект → **Settings** → **Environment Variables**.
2. Добавьте переменную **REVALIDATE_SECRET** — придумайте длинный случайный пароль (например сгенерируйте на [random.org](https://www.random.org/strings/) и сохраните в надёжном месте).
3. Примените к окружениям Production (и при желании Preview).

**2. Webhook в Storyblok**

1. Storyblok → ваше пространство → **Settings** (иконка шестерёнки) → **Webhooks**.
2. **Add webhook**.
3. **URL:** `https://ваш-домен.vercel.app/api/revalidate` (подставьте реальный домен, например `irinaexamprep.com`).
4. **Trigger:** отметьте **Story published** (и при желании **Story unpublished**).
5. В настройках webhook найдите способ передать секрет. В нашем API секрет ожидается:
  - в заголовке **x-revalidate-secret**, или
  - в query: `?secret=ваш_REVALIDATE_SECRET`.
   В Storyblok в полях webhook укажите заголовок `x-revalidate-secret` = значение вашего `REVALIDATE_SECRET` (если интерфейс это позволяет). Если нет — можно вызывать так: `https://ваш-домен.vercel.app/api/revalidate?secret=ваш_секрет` (тогда секрет будет в URL; лучше использовать заголовок, если доступен).
6. Сохраните webhook.

**3. Проверка**

Опубликуйте любую историю (например home). В Storyblok в разделе Webhooks обычно видна история вызовов — должен быть успешный запрос (200). Откройте сайт (лучше в режиме инкогнито или с принудительным обновлением) — должен отображаться обновлённый контент.

Реализация: `src/app/api/revalidate/route.ts` — проверяет секрет и вызывает `revalidatePath` для `/`, `/courses`, `/methodology`, `/free-resources`, `/offer`, `/payment-refund`, `/privacy`.
