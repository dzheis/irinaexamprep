# План интеграции Storyblok

Клиент хочет управлять всем контентом сайта из одной CMS: заголовки, тексты, фото, блоки с видео, цены и т.д. **Реализовать это со Storyblok можно.**

---

## Что будет управляться из CMS

| Место на сайте | Сейчас в коде | Что отдаём в Storyblok |
|----------------|----------------|-------------------------|
| **Главная** | `page.tsx` → title, description, imageUrl | Hero: заголовок, описание, фото. Остальные секции — свои блоки/поля. |
| **Hero** | Props + TEACHER_INTRO в HeroSection | Заголовок, подзаголовок, фото, текст под кнопками. |
| **Обо мне (About)** | AboutSection: заголовок + 8 абзацев + 7 сертификатов | Заголовок, список абзацев, список картинок сертификатов. |
| **Блок преимуществ (Features)** | features[] в FeaturesSection | Заголовок секции, подзаголовок, список: заголовок, описание, иконка (Lottie можно оставить по ключу или заменить на картинку). |
| **Курсы (страница /courses)** | COURSE_CARDS + COURSE_DESCRIPTIONS | Список курсов: название, slug, картинка, длинное описание. |
| **Методика (/methodology)** | METHODOLOGY_VIDEOS | Список модулей: id, videoId (YouTube), название, описание, цена. |
| **Отзывы (Testimonials)** | testimonials[] | Список: имя, роль, текст, аватар, картинка сертификата. |
| **Блок CTA** | Заголовки, текст, ссылки в CTASection | Заголовок, подзаголовок, текст кнопок, ссылки соцсетей. |
| **Курсы/Методика/Ресурсы (карточки на главной)** | CoursesMethodologySection: заголовки, ссылки, lorem | Заголовки карточек, ссылки «Подробнее», краткие тексты. |
| **Шапка** | Header: логотип, пункты меню | Текст логотипа, подпись, пункты меню (название + ссылка). |
| **Подвал** | Footer | Текст копирайта, при желании ссылки. |
| **Оферта** | Текст в offer/page.tsx | Один большой rich text или несколько блоков. |
| **Free Resources** | Заголовки, текст, ссылка на файл | Заголовок страницы, описание, ссылка на sample-download. |

Фото и картинки хранятся в медиабиблиотеке Storyblok, ссылки на файлы отдаются через поля (Asset или ссылка).

---

## Два варианта интеграции

### Вариант A: «Одна история на тип страницы» (рекомендуется на старт)

- В Storyblok заводим **типы контента (Content types)** под страницы: Home, Courses, Methodology, Free Resources, Offer, + глобальный Config/Header/Footer.
- У каждой истории — **поля и повторяемые блоки** (например, список курсов, список отзывов). Структура страницы фиксирована (какие секции есть), редактируются только тексты, цены, медиа, ссылки.
- В Next.js по маршруту определяем, какую историю запрашивать (`home`, `courses`, `methodology` и т.д.), загружаем её через API Storyblok и **передаём данные в существующие компоненты** (HeroSection, AboutSection, courses-client и т.д.). Разметку и стили почти не трогаем.
- Плюсы: быстрее внедрить, меньше рефакторинга, клиенту проще править «формы» (поля и списки). Минус: добавлять новые типы блоков на страницу будет сложнее (нужны правки в коде и в типах Storyblok).

### Вариант B: «Всё блоками (Blok-based)»

- Каждая секция (Hero, About, Features, CourseCard, VideoBlock, Testimonials, CTA и т.д.) — **отдельный Blok** в Storyblok. Страница (например Home) — это «контейнер» с массивом блоков; редактор добавляет/удаляет/переставляет блоки.
- В Next.js один общий шаблон страницы: рендер по `story.content.body[]` и маппинг типа блока на React-компонент. Максимальная гибкость, но больше работы по схеме в Storyblok и по коду (каждый блок = компонент + тип в CMS).
- Имеет смысл переходить на это, когда клиенту понадобится самому собирать страницы из блоков и часто менять структуру.

**Практичный путь:** начать с **варианта A**, вынести весь текущий контент в Storyblok (заголовки, тексты, фото, цены, видео, списки). Когда потребуется «собирать страницу из блоков» — расширить модель до варианта B.

## Что нужно сделать технически

1. **Storyblok**
   - Зарегистрировать пространство (space) на [storyblok.com](https://www.storyblok.com).
   - Создать Content types и поля (см. таблицу выше).
   - Заполнить контент (скопировать с сайта или вручную).
   - В настройках пространства взять **Access Token** (Preview/Draft и при желании Public для продакшена).

2. **Проект (Next.js)**
   - Установить `@storyblok/react`.
   - Добавить в `.env.local`: `NEXT_PUBLIC_STORYBLOK_ACCESS_TOKEN=...`.
   - Инициализировать Storyblok (RSC или client) и заменить источники контента:
     - главная: запрос `cdn/stories/home` (или по slug) → передать в `HomeClient` и секции;
     - курсы: запрос данных для страницы курсов → в `courses-client`;
     - методика: запрос данных для методики → в `methodology-client`;
     - free-resources, offer — аналогично;
     - глобальные данные (шапка, подвал) — одна общая история или глобальный singleton, подставлять в Layout/Header/Footer.
   - Медиа: картинки из Storyblok отдаются URL вида `https://a.storyblok.com/...` — можно использовать `next/image` с доменом `a.storyblok.com` в `next.config`.
   - По желанию: включить **Visual Editor** (bridge) для редактирования контента с превью на сайте.

3. **Резерв (fallback)**
   - Пока контент не заполнен в Storyblok или при ошибке API — использовать текущие захардкоженные данные, чтобы сайт не падал.

После этого клиент сможет в Storyblok править заголовки, тексты, фото, цены, видео, списки курсов/отзывов/модулей и т.д. без правок в коде.

## Что уже сделано (пилот)

- Установлен `@storyblok/react`, в `.env.local` добавлена переменная `NEXT_PUBLIC_STORYBLOK_ACCESS_TOKEN`.
- В `next.config.ts` разрешён домен картинок `a.storyblok.com`.
- В `src/lib/storyblok.ts`: инициализация SDK (RSC), функция `fetchStory(slug)` для загрузки истории по slug.
- Главная страница: в `app/page.tsx` запрашивается история с slug **home**. Если токен не задан или запрос неудачен — используются захардкоженные значения (fallback).
- Hero-секция получает из Storyblok: `title`, `description`, `intro`, `image` (URL фото). Тип контента описан в `src/lib/storyblok-types.ts` (`HomeStoryContent`).

### Как создать историю «Главная» в Storyblok

1. В личном кабинете Storyblok: Content → создать новую историю.
2. Slug задать **home** (без слэша).
3. В блоке контента добавить группу/блок **hero** с полями:
   - **title** (Text) — заголовок, например «Ирина Петрова».
   - **description** (Text, опционально) — подзаголовок под кнопками.
   - **intro** (Textarea, опционально) — абзац про преподавателя (если пусто — используется текст по умолчанию из кода).
   - **image** (Asset) — фото преподавателя (если пусто — используется локальное фото с сайта).
4. Опубликовать историю (Publish).
5. В настройках пространства (Settings → Access tokens) скопировать **Preview/Draft** или **Public** токен и вставить в `.env.local` в `NEXT_PUBLIC_STORYBLOK_ACCESS_TOKEN`.

После этого контент Hero на главной будет подтягиваться из Storyblok. Остальные секции и страницы можно подключать по тому же принципу (см. таблицу выше).

## Следующий шаг

1. Создать пространство Storyblok (если ещё не создано), получить токен и заполнить историю **home** как выше.
2. Постепенно переносить остальные страницы и глобальные блоки (курсы, методика, header, footer, оферта).
3. При желании включить Visual Editor: указать URL сайта в настройках Storyblok и при необходимости обернуть приложение в `StoryblokProvider` из `@storyblok/react`.
